## 一、作品内容

### 1.1 作品是什么

ProteinLens 是一个**浏览器即开即用**的蛋白质结构预测与**置信度判读**工作台。它把过去散落在命令行、Python/GPU 环境、多个预测工具之间的整条链路，收进一个网页：用户输入 UniProt ID、原始序列或 FASTA（也支持用一句自然语言描述目标蛋白，平台自动检索候选），平台即开启一个智能体会话，由会话内的模型自主规划并调用预测工具完成结构折叠，最终给出带**完整置信度体系**的结果。

它同时是一个「平台自检」的作品：平台自身接受国际公开学术基准 CASP14 的检验，把预测结果与 RCSB 实验解析结构逐靶比对、由服务端独立复算精度分数，并把模型自报置信度与实测值的校准关系公开成图——**包括对自己不利的部分**。

### 1.2 要解决的真问题

蛋白质结构预测这两年进展飞快，但对非生物信息学用户真正的门槛从来不是"有没有工具"，而是三件事：

1. **环境门槛**：主流工具（AlphaFold、ColabFold、Boltz-2 等）需要命令行、Python 与 GPU 环境，多工具之间还要手动拼装输入输出；
2. **判读门槛**：产出一个 PDB 文件不等于可用结果。实测数据显示，同一套单序列从头预测流程在 CASP14 靶标上的精度谱可以横跨 0.29–0.95（Cα-lDDT），普通用户却缺乏判断"这次预测到底可不可信"的能力；
3. **验证门槛**：谁都可以展示一张漂亮的结构图，但少有人让第三方基准来检验自己的输出。

本作品把这三件事合成一个整体：**预测 + 置信度判读 + 外部基准自检**。

### 1.3 面向哪两类用户

- **零生信背景的用户**：不需要装任何软件，打开网页即可完成预测，并通过 pLDDT 着色、置信度曲线、分段统计等可视化，一眼判断这次结果可信不可信；
- **Agnes Harness 生态的科研助手场景**：以一个真实科研工作流（任务规划 → 工具编排 → 结果验证 → 外部基准检验）验证通用智能体底座承接专业科学任务的能力。

## 二、实现方案

### 2.1 总体架构

从浏览器到结果验证是一条完整数据通路：

**浏览器（平台 surface，React + TypeScript）** → **Caddy 2.10.2 反向代理 + 登录门**（`forward_auth` 会话 cookie）→ **平台服务端（Node + TypeScript）** → **Agnes Harness（AGH）daemon** → **agent 会话** → **AGH 工具与服务** → **外部模型/数据接口与三级算力路由** → **服务端归档与基准打分**。

### 2.2 智能体底座：每个任务 = 一个 AGH agent 会话

AGH 在本作品中不是可选组件，而是执行底座：**每个预测任务对应一个 AGH agent 会话**（`sdk.session.new({ cwd, preset: 'standard' })`，`orchestrator.ts:381`），并通过 `session.prompt(buildPrompt(type, input))` 注入按任务类型生成的结构化提示词。agent 在会话内规划「取序列 → 折叠预测 → 置信度分析」的执行顺序，并按需调用能力。

值得强调：**模型真的在做决策，不是被硬编码的流水线**。最直接的证据是 CASP14 长链靶标 T1024（408 aa 膜蛋白）的会话日志——`predict_structure` 对 >1000 aa 直接拒绝，约 400 aa 送公共 ESMFold 端点被拒（HTTP 413）；agent **读取该失败信息后自主改档**，改调 `predict_complex` 走 Boltz-2 长链档。这条"读错误信息 → 换工具重试"的链路是模型在会话内完成的。

### 2.3 能力注册与工具编排

平台向 AGH 注册了两层能力：

- **工具（`agnes.registerTool`）**：`predict_structure`（单体预测）、`predict_complex`（复合物/长链预测）、`batch_predict`（批量）、`uniprot_search`（序列检索）、`compare_with_alphafold`（与参考结构对比）；
- **服务（`ctx.services.register`）**：`protein.structure`（链感知结构解析）、`protein.report`（报告渲染）、`protein.pae`（PAE 热图数据）、`protein.file`（产物读取）。

### 2.4 过程可观测：事件流账本式归约

前端进度页不是"猜"出来的，而是对 `session.events()` 做**账本式归约**：每次工具调用在事件流中留有"工具开启 / 结果关闭"成对事件，进度页把这对事件实时映射成阶段点亮。这使"执行中"的呈现与真实执行状态严格一致，不会出现假进度。

### 2.5 断线可恢复

页面关闭或刷新后，通过 `sdk.session.load`（`orchestrator.ts:538`）重新连接会话并**回放事件日志**：任务不会丢，进度照常推进，结果照常出现。前端只是观察窗口，执行体在服务端。

### 2.6 三级算力路由（核心工程方法之一）

预测请求按三级分发，任一级失败**静默落回下一级**，对上层 agent 与前端完全透明：

1. **自建 GPU worker**：家用 RTX 4060 经反向 SSH 隧道挂载为服务器本机 `127.0.0.1:7610`。分发前探活 1.5 s，提交窗口 22 分钟；worker 侧为串行 GPU 队列，双端只绑回环，Bearer token 鉴权；
2. **Boltz 托管 API**（团队自购密钥）：无 GPU 时的可用档位；
3. **本地开源权重**（`boltz_community 2.10.12`，MIT）：VPS 上的兜底推理档；
4. 三级都不可用时返回**可执行的配置提示**，而不是静默失败。

关键设计取舍：**worker 永远只是加速器，不是依赖项**。GPU 机器关机时该档静默消失，任务照常完成，只是速度不同——这一点已被真实停隧测试验证（秒级 failed + 可执行提示，不会假完成）。

### 2.7 模型与调用方式

| 项 | 内容 |
| --- | --- |
| 主档模型 | **Agnes 3.0 Flash**（`agnes-3.0-flash`），经 Agnes AI 网关（OpenAI 兼容协议）调用，原生工具调用，200K 上下文 |
| 备用路由 | **Doubao Seed 2.0 Pro**（`doubao-seed-2-0-pro-260215`，火山方舟端点，Anthropic messages 协议），网关抖动时接管，对上层透明 |
| 使用环节 | 每个任务会话的规划与工具调用决策，全部任务（含 CASP14 十靶）均由该模型会话驱动 |
| 证据 | 平台会话库中 `agnes-3.0-flash` 出现 265 处，备用模型 0 处；每个任务的会话事件流中可见该模型发起的工具调用事件 |

### 2.8 部署与运行环境

- **公网入口**：腾讯云轻量应用服务器直连（`http://118.25.194.247/platform/`）。裸 IP 无 TLS 证书，走 http 明文；WebSocket 走 `ws://118.25.194.247/agnesd`；
- **反代与登录门**：Caddy 2.10.2（Ubuntu 24.04 自带版本不认 `basic_auth` 等指令，必须用官方二进制），以 `forward_auth` 实现会话 cookie 登录门，替代早期的 HTTP Basic Auth；
- **工具码发布纪律**：改工具代码不能只改源码树——daemon 只加载 **profile 安装快照**，必须走 `agh-update-pkg`（install → update → trust → enable）并校验安装目录哈希，再重启 daemon 与 web。

### 2.9 前端渲染与零依赖

3D 结构、PAE 热图、缩略图全部由项目自有代码实时生成（Canvas / WebGL），**未使用任何第三方图片、字体或 3D 模型资产**；三个业务包（platform / predictor / view）**运行时零 npm 依赖**。

## 三、核心功能

### 3.1 输入识别与前置校验（提交前就能看到解析结果）

输入框下方有实时识别条，在**提交之前**就告诉用户平台"读到了什么、会丢掉什么"：

- 粘贴 `P69905` → 识别为「UniProt ID · P69905」；
- 粘贴序列 → 识别为「原始序列 · N aa」；
- 粘贴多条 FASTA → 取首条并提示「其余 N 条将忽略」；
- 序列里混入数字 → 黄条警告「含数字或特殊字符，无法识别为序列」；
- 输入一句描述（如 `p53 human`）→ 识别为「自然语言描述 · 将检索 UniProt 候选」；
- 批量页签输入 10 个 ID → 提示「8 个 UniProt ID」+「最多 8 个，仅取前 8 个」，**服务端同样只处理前 8 个**（前端与归档双侧一致，显式截断，绝不静默丢弃）；
- 复合物页签 → 统计「2 条链 · 共 N aa」，并对不足 5 aa 的链提示「将被忽略」。

### 3.2 任务提交与执行

三种任务：单体预测、复合物预测（支持多链 + 配体 SMILES）、批量预测。提交后进入阶段进度页（取序列 → 折叠预测 → 置信度分析），可随时关闭页面，服务端继续执行。

### 3.3 结果判读（本作品的核心价值）

每个结果页自带一套可判读的置信度体系：

- **3D 结构**：拖拽旋转、滚轮缩放，按 **pLDDT 逐残基着色**（蓝=高置信 → 红=低置信）；
- **置信度曲线**：鼠标悬停某残基，3D 上对应位置联动高亮；支持序列条拖选区段；
- **分段统计**：自动识别并列出连续低置信区段，直接告诉用户"哪一段不可信"；
- **复合物专属**：链间置信度 **ipTM**、整体 pTM、配体结合概率，以及 **PAE 误差热图**（0 Å → 32 Å 色标，含链边界虚线与残基刻度，点击可回读具体残基对误差）。

### 3.4 归档与报告墙

任务完成后由服务器拉取工作区产物归档（单次 POST + 服务端读取，含元数据硬不变量）。归档使得**换设备、换会话打开"全部任务"时结果页可完整重建，不依赖原页面在线**。报告墙支持类型筛选、标题搜索与「最高分」排序（按平均 pLDDT 降序，未打分项排后）。

### 3.5 一键分享自包含报告

任意结果可导出**自包含 HTML 报告**：内嵌 PNG 快照、pLDDT 评分、完整报告 JSON 以及一个可拖拽旋转的交互式 3D 视图。实测导出体积约 12 万字节，报告在无网络、无平台的纯本地环境下仍可打开与交互（拖拽旋转、滚轮缩放均已自动化验证）。

### 3.6 外部能力调用

- **与 AlphaFold DB 对比**：对单体结果调用 `compare_with_alphafold`，以 Horn 四元数最优叠合计算 Cα-RMSD，核心区 RMSD < 2 Å 判定「与参考高度一致」；
- **UniProt 检索**：顶栏「检索」页可结构化搜索（如 `hemoglobin`），命中表支持行内 ▶ 一键预测与勾选多条「预测所选」。

### 3.7 平台自检：CASP14 基准页

平台内置「基准」页，用 CASP14 公开靶标集在**公网真实管线**上跑，以 RCSB 实验解析结构为真值，由**服务端独立复算** Cα-lDDT（Mariani et al. 2013 口径）与 Cα-RMSD，并输出 pLDDT 校准直方图。十个公开靶标（106–408 aa）中，**九个完成自动打分，一个（408 aa 膜蛋白 T1024）如实显示「待运行」**。

### 3.8 异常处理

- 网关抖动（超时/限流/连接中断）自动重试最多两次；401 鉴权失败自动换头重试；
- 失败任务如实展示失败原因行，并提供「↻ 重新提交」一键原样重跑；
- 运行中支持两键取消（点「取消」→「确认取消」），取消态与失败态严格区分（用户主动取消不会被记为错误，也不触发自动重试）；
- GPU worker 缺席时静默落回 API / 本地档，任务照常完成。

## 四、技术亮点

### 4.1 智能体底座是"真用"，不是"套壳"

多数"AI 应用"把模型当成一个文本生成器。本作品中 AGH 承担的是**执行底座**：会话管理、能力注册、工具编排、事件流回放、断线恢复。平台对 `session.events()` 做账本式归约驱动进度，`sdk.session.load` 支持断线重连回放——这两项是"页面只是观察窗口"这一卖点的技术前提。T1024 会话日志中"ESMFold 413 → 读取失败信息 → 自主换档 Boltz-2"的完整链路，是模型决策能力的直接证据。

### 4.2 三级算力路由与"零依赖降级"

自建 GPU worker → 托管 API → 本地开源权重，任一级失败静默降级。设计上刻意让 **worker 只是加速器而非依赖项**：它缺席时平台功能完整、只是更慢。这把"家用 GPU 不稳定"这个现实约束，转化成了对用户不可见的实现细节。

### 4.3 把"结果可不可信"做成了产品功能

这是本作品与同类工具最本质的区别。产出结构只是第一步，**置信度体系**（pLDDT 逐残基着色、置信度曲线与 3D 联动、连续低置信区段、复合物 ipTM 与 PAE 热图）让非专业用户也能判读质量；而**校准直方图**进一步检验"模型自报的置信度是否诚实"——实测两者高度一致（如 T1025 自报 94.6 vs 实测 95.2，T1046s2 自报 85.0 vs 实测 85.9），也存在如 T1056 自报 70.3 而实测 81.7 的偏保守情形。**偏离也如实进图**。

### 4.4 平台自身接受外部学术基准检验

不是自说自话，而是把 CASP14 公开靶标集接入真实管线，用 RCSB 实验结构做真值，**服务端独立复算**精度分数，逐靶公开参考 PDB ID 以便复核。已完成的九个靶标成绩头部突出：**T1025 达 Cα-lDDT 0.952 / 全残基 Cα-RMSD 0.65 Å**，T1030 0.943、T1046s2 0.859、T1056 0.817；同时如实呈现 0.29–0.52 的低分档——**分数谱全谱公开、不做挑选**，因为单序列从头预测的难度是真实存在的。另有独立参考锚点：血红蛋白 α（P69905）预测与 AlphaFold DB 参考结构核心区 Cα-RMSD **0.31 Å**。

### 4.5 诚实工程：把失败也做成可验证的证据

408 aa 膜蛋白 T1024 在公网环境三次运行均未完成，平台**如实显示「待运行」，不粉饰、不重试赌博**。这一靶的排查过程反而是最完整的工程部分：

- 前两次失败源于两处**分层超时缺陷**——worker HTTP 服务默认 300 s 请求超时、客户端 fetch 默认 300 s 头部超时；长链折叠常超过 5 分钟，响应被提前掐断，且错误被降级提示掩盖，极易误判为"缺少 API key"；
- 两处缺陷均已定位修复，并顺带修正了包发布链路（必须发布到 profile 安装快照而非仅改源码树）；
- 第三次全部修复生效后，被团队保留的**单任务 20 分钟保护上限**终止——真瓶颈是长链折叠依赖的**公共 MSA 服务排队时长不可控**（同日实测 14 分钟与超过 20 分钟两档，而 GPU 推理本身仅约 2 分钟）。worker 侧留有同日完整折叠产物（pTM 0.78 / pLDDT 0.905）为证；
- 团队按设计取舍**不放宽上限**，如实保留失败记录，三次会话日志与修复 commit 链公开可溯。

### 4.6 结果验证的独立性

基准打分在**服务端**完成，不依赖前端、不依赖页面在线：前端只负责呈现。这让"平台自检"具备可信度——分数不是前端算给自己看的。

### 4.7 可复现性

仓库内附 `dev-tests` 探针套件，覆盖归档装配（13 项断言）、预测流全生命周期（42 项）、Cα-lDDT 打分数学（22 项）共 **77 项单元断言**，另有公网端到端探针（登录 → 提交 → 归档 → 重建结果页）。typecheck 与 lint 门禁干净。文档中给出的关键分数、比对结论与复现命令一一对应，评审可现场抽查。

## 五、小结

ProteinLens 的主体工作可以概括成一句话：**把蛋白质结构预测从"能跑出文件"推进到"能判断可不可信、并接受外部基准检验"**。它用 Agnes Harness 作为执行底座承载真实的多步工具编排，用三级算力路由把不稳定的本地 GPU 变成对用户不可见的加速档，用完整的置信度体系与非装饰性的校准检验解决判读问题，并且——**把自己跑失败的那一靶也如实留在页面上**。
