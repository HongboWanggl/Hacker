## 一、基本信息

**项目名称**

```
ProteinLens 蛋白透镜——基于 Agnes Harness 的蛋白质结构预测与置信度判读工作台
```

**参考方向**（按填报系统提供的候选项多选，建议勾选）

```
生命科学与医药健康 / 智能体（Agent）应用 / 科学计算工具
```

**项目摘要**（约 200 字）

```
本项目是双层定位的作品：它既是一个即开即用的蛋白质结构预测前端（面向零生信背景用户，
浏览器打开即可用），也是一个运行在 Agnes Harness 上的科研助手——以一个完整科研工作流
（任务规划 → 工具编排 → 结果验证 → 外部基准检验）验证通用智能体底座承接专业科学任务的能力。

面向零生物信息学背景的用户，把"蛋白质结构预测"从命令行工具变成浏览器即开即用的智能体工作台。
用户只需输入 UniProt ID、原始序列或 FASTA，平台即在 Agnes Harness 上开启一个 agent 会话，
由会话内的 Agnes 模型自主规划并调用预测工具（ESMFold 单体 / Boltz-2 复合物与长链），
经三级算力路由（自建 GPU worker → 托管 API → 本地开源权重）完成折叠。
每个结果自带完整置信度体系（pLDDT 逐残基着色、置信度曲线、分段统计、复合物 ipTM 与 PAE 热图），
让非专业用户也能判断"这次预测可不可信"。平台自身接受外部学术基准检验：CASP14 公开靶集在公网
真实管线完成自动打分（Cα-lDDT / Cα-RMSD，RCSB 实验结构为真值），并公开 pLDDT 校准直方图。
```

**问题来源与目标**

```
问题来源：蛋白质结构预测工具（AlphaFold、ColabFold、Boltz-2 等）对非生物信息学用户门槛很高——
需要命令行、Python/GPU 环境、多工具手动拼装；更关键的是，产出一个 PDB 文件不等于可用：
预测质量参差（CASP14 实测 lDDT 谱 0.29–0.95），而普通用户缺乏判断"这次预测可不可信"的能力。

项目目标：
1. 三种输入（UniProt ID / 原始序列 / FASTA）实时识别，三种任务（单体预测、复合物预测、批量预测）一键提交；
2. 每个结果自带置信度体系（pLDDT 着色、置信度曲线、分段统计、复合物 ipTM 与 PAE 热图），让非专业用户能判断可信度；
3. 平台自身接受外部学术基准检验（CASP14 靶集，Cα-lDDT / Cα-RMSD 打分 + pLDDT 校准直方图）；
4. 历史归档、对比分析、可分享的自包含 HTML 报告。
```

## 二、技术信息

**AGH 作用**（Agnes Harness 在本项目中的角色）

```
AGH 是本平台的智能体执行底座，不是可选组件：每个预测任务 = 一个 AGH agent 会话
（sdk.session.new({ cwd, preset: 'standard' })，orchestrator.ts:381）。
- 能力注册：预测与查询能力经 agnes.registerTool（predict_structure / predict_complex /
  batch_predict / uniprot_search / compare_with_alphafold）与 ctx.services.register
  （protein.structure / protein.report / protein.pae / protein.file）注册，由会话内 agent 规划调用；
- 过程可观测：平台对 session.events() 做账本式归约（工具开启/结果关闭成对事件）实时驱动进度页；
- 断线可恢复：页面关闭/刷新后经 sdk.session.load（orchestrator.ts:538）重连并回放事件日志，
  任务不丢、进度真实；
- 结果可验证：任务完成后由服务器拉取工作区产物归档，「基准」页以 RCSB 实验结构为真值独立打分。
```

**Agnes 模型名称 / 版本 / 使用环节 / 调用方式**

| 项 | 内容 |
| --- | --- |
| 名称与版本 | **Agnes 3.0 Flash**（模型 ID `agnes-3.0-flash`，主档 slot: primary） |
| 使用环节 | 每个任务会话的**规划与工具调用决策**：识别输入类型、决定调用哪个预测工具、读取工具失败信息后换档重试、汇总结果成报告。CASP14 靶集、单体/复合物/批量全部任务均由该模型会话驱动 |
| 调用方式 | 经 **Agnes AI 网关**（`https://api.agnes-ai.cn/v1`，OpenAI-compatible 协议）调用；原生工具调用（toolCallFormats: native），200K 上下文、单次最大 65536 tokens，思考链回放策略 drop |
| 配置位置 | VPS 平台 profile 的 `profile.yaml` 自有路由（`route: agnes-ai`），凭据存于 `data/secrets`，不进代码仓库 |
| 备用路由 | 网关抖动时由 **Doubao Seed 2.0 Pro**（`doubao-seed-2-0-pro-260215`，火山方舟 agent-plan 端点，Anthropic messages 协议，256K 上下文）接管，对上层透明 |
| 使用证据 | 平台会话库 `sessions.db` 中 `agnes-3.0-flash` 出现 **265 处**、备用模型 0 处——全部平台会话（含 CASP14 十靶）均由 Agnes 3.0 Flash 驱动；每个任务的会话事件流中可看到该模型发起的工具调用事件（开启→结果成对） |

**数据 / 代码 / 专业软件 / 仿真环境 / API / 设备接口**

```
数据：UniProt（序列查询）、RCSB PDB（实验结构真值）、AlphaFold DB（参考预测结构，CC BY 4.0）、
      CASP14 公开靶标序列（targets.json）
代码：Node.js + TypeScript + React（前端）、AGH 平台扩展（extensions）、dev-tests 探针套件
专业软件：Boltz-2（boltz_community 2.10.12，MIT 本地权重）、ESMFold 公共折叠端点、
      ColabFold 公共 MSA 服务（boltz --use_msa_server）
仿真/运行环境：VPS（Ubuntu，Caddy 反代 + AGH daemon + Web）、自建 GPU 主机
      （RTX 4060，经反向 SSH 隧道挂载为本机 127.0.0.1:7610，worker 串行 GPU 队列）
API：api.esmatlas.com（ESMFold）、Boltz 托管 API（自购备用）、Agnes AI 网关、火山方舟 Ark、api.uniprot.org、files.rcsb.org
设备接口：GPU worker HTTP 接口（Bearer token 鉴权、双端仅绑回环）、平台通过三级路由
      （worker → 托管 API → 本地权重）对上层完全透明
```

## 五、运行证据

**1. AGH 执行记录**

```
- 会话级：每个任务对应一个 AGH agent 会话（orchestrator.ts:381 创建；orchestrator.ts:538 断线回放）；
  归档任务元数据保存 sessionId 可回溯对应会话；
- 工具调用过程：agent 每次工具调用在会话事件流中留有开启/结果成对事件，前端进度页即对该事件流实时归约；
- 平台侧：VPS daemon 运行日志 + Caddy 访问日志 + 平台 archive/（report.json / model.pdb / pae.json /
  缩略图），三者时间戳可交叉印证一次真实预测的发生。
```

**2. 工具 / 设备调用链（≥1 条，此处给两条）**

```
链 A（含设备接口，CASP14 T1024，408 aa 膜蛋白）：
  composer 输入序列 → agent 会话调 predict_structure → ESMFold 公共端点返回 HTTP 413（超长拒绝）
  → agent 读取失败信息自主换档 predict_complex → 三级路由第一档 = 自建 RTX 4060 GPU worker
  （反向 SSH 隧道 127.0.0.1:7610）→ worker 侧完成 Boltz-2 折叠，产物 pTM 0.78 / pLDDT 0.905

链 B（完整成功链，P69905 血红蛋白 α，141 aa）：
  UniProt ID 输入 → predict_structure（ESMFold）→ protein.report / protein.pae 服务渲染置信度
  → compare_with_alphafold（Horn 四元数叠合，核心区 Cα-RMSD 0.31 Å，判定"与参考高度一致"）
  → 服务器归档（taskId tmv7ue2s0ujd8），报告含逐残基 ΔpLDDT 可复核
```

**4. 关键配置与专业验证结果**

```
关键配置：profile.yaml 自有模型路由（agnes-ai 主档 + ark 备用）；三级算力路由
```

## 六、测试样例（正常 / 边界 / 失败三类）

```
正常（3）：单体 P69905（ESMFold 成功，pLDDT 94.7，与 AlphaFold DB 核心区 0.31 Å）；
        复合物（双链 + 阿司匹林 SMILES，Boltz-2 多链 PDB + PAE 热图 + ipTM）；
        归档往返（换会话/设备打开"全部任务"，结果页完整重建）。
边界（5）：>1000 aa 直接拒绝；约 400 aa 送 ESMFold 被拒（HTTP 413）→ 失败信息指路
        predict_complex 并完成换档；批量 >8 个 ID 双侧显式截断（前端黄条 + 服务端 slice，不静默丢弃）；
        >800 残基 PAE 按块 mean-pool 降尺度并标注 scale；归档超预算时 pdb-* 按体积丢弃、report.json 必存活；
        路径穿越 ../../etc/passwd 解析为空。
失败（5）：CASP14 T1024 三次公网运行失败——两处分层超时缺陷已定位修复（commit 41ace5e / 123a214），
        第三次被保护性单任务 20 分钟上限终止（公共 MSA 服务排队时长不可控，当日实测 14 min 与 >20 min 两档），
        基准页如实显示"待运行"；401 鉴权失败自动换头重试；任务失败呈现与「↻ 重新提交」；
        瞬时抖动自动重试≤2 次；GPU worker 缺席时静默落回 API/本地档，任务照常完成。
（每条均有对应自动化断言或可现场复现的公网操作，映射见《4-运行与验证证据》§四）
```
